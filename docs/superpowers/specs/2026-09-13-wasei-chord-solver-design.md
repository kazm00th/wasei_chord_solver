# 和声記号→構成音導出ツール（wasei_chord_solver）設計仕様

## 背景・目的

`HANDOFF.md`（島岡譲系和声理論の研究ノート）で本セッション中に確立した「五度圏インデックスによる構成音導出アルゴリズム」（§5）を、実際に動くプログラムとして実装する。目的は、`○度調の（○度の○度）`のような入れ子構造を持つ和音記号（準/同主/プラス/マイナス、ナポリII度、ドリアIV度、変位VII等を含む）から、構成音・ピッチクラス・導出ステップを機械的に算出すること。

## スコープ

- **v1で実装する**（フルスコープ、後回しにしない）:
  - 内部調の入れ子（`innerChain`）: 度数調・準・同主・プラス・マイナス・ナポリII調・変位VII調、深さ無制限
  - 和音自体の特殊形（`chord.special`）: 準（借用和音）・ナポリII度・ドリアIV度・変位VII度
  - 形体（7/9/付加6/付加4）・上変/下変・転回・根省/5省
  - 出力: 構成音（ドイツ音名）・ピッチクラス（0-11）・導出ステップの構造化ログ
- **v1で扱わない**（既存HANDOFFでも未確定/範囲外の事項）:
  - III度族・VI度単独・V度のV度族に固有の限定進行音規定（§0.3未確認事項）
  - 転調進行そのもの（この解析対象は単一の和音記号であり、進行の妥当性判定はしない）
  - `V11`/`II9`/`II11`等、§3未収録の上位和音

## アーキテクチャ

- **`core.js`**: 計算ロジックのみを持つ、DOM非依存の純粋関数群。ブラウザからは`<script src="core.js">`、テストからはNodeの`require`で共有する（単一HTML化は不要、`index.html`から素直に読み込む）。
- **`index.html`**: 動的ドロップダウンUI（「内部調を追加」ボタンで`innerChain`の要素を無制限に追加）。`core.js`の関数を呼び出し、結果を表示するだけの薄い層。
- **`test/`**: Node標準`assert`によるユニットテスト。ビルド・外部依存ライブラリなし。

## データモデル

```js
{
  mainKey: { index: 0, quality: "major" }, // 五度圏インデックス直接入力（任意の重変位可）、長調/短調

  innerChain: [   // 外側→内側の内部調演算子の列（0個以上、順序が意味を持つ）
    { type: "degree", degree: "III" },   // ○度調
    { type: "quasi" },                   // 準（自然短調オフセット表に切替、根音index変化）
    { type: "relative" },                // 同主（長調オフセット表に切替、根音index変化）
    { type: "plus" },                    // プラス（同主長調化、根音index不変）
    { type: "minus" },                   // マイナス（同主短調化、根音index不変）
    { type: "napoli" },                  // ナポリII調（音程ベース定義、§7.3.1）
    { type: "raisedVII" },               // 変位VII調（音程ベース定義、§7.3.1）
  ],

  chord: {
    degree: "IV",          // 局所的な"いまの調"におけるベースの度数（I〜VII）
    special: null,         // null | "quasi" | "napoli" | "doric" | "raisedVII"
                            // ＝和音そのものの特殊形。§2の固定テーブルを直接引く。
                            // innerChainの同名演算子（内部調を新規に確立する）とは別物。
    form: { seventh: false, ninth: false, add6: false, add4: false },
    alteration: { up: false, down: false },   // 上変・下変（±7）
    omission: { root: false, fifth: false },  // 根省・5省
    inversion: 0            // 転回指数（0=基本形）
  }
}
```

### 内部調レベル vs 和音レベルの「準」の違い（重要な設計判断）

同じ「準」という記号が2つの異なる意味を持つことがユーザーとの対話で判明した。

- **内部調レベル**（`innerChain`の`quasi`）: `準X度調`。新しい内部調を確立し、その中で改めてステップ1〜2の手順を再帰的に適用する（§7.9/§5）。
- **和音レベル**（`chord.special = "quasi"`）: `準IV度`のように、**内部調を新たに作らず**、いま構築中の和音1つだけを§2の固定パターン（例：`準IV度 = f as c`）で直接変化させる。

この2つは計算方法が全く異なるため、データモデル上も別フィールド（`innerChain`の要素 vs `chord.special`）として明確に分離する。`chord.special`は排他的な1個の値であり、`degree`との組み合わせに理論的な制約がある（例：`napoli`はII度のみ、`doric`はIV度かつ短調文脈のみ、`raisedVII`はVII度かつ長調文脈のみ）。UIは選択中の`degree`に応じて`special`の選択肢を絞り込む。

## コアアルゴリズム（`deriveChord(spec)`）

§5に定式化済みの5ステップをそのまま関数化する。

1. **ステップ0**: `mainKey.index`を起点にする。
2. **ステップ1（内部調の確立、`innerChain`を外側から内側へ畳み込み）**:
   - `degree`: 長調オフセット表／自然短調オフセット表（現在の質に応じて選択）を引いて根音indexを更新。
   - `quasi`/`relative`: 以後参照するオフセット表を強制的に切替（根音indexは不変）。
   - `plus`/`minus`: 以後参照するオフセット表を強制的に切替、かつ質そのものを固定（根音indexは不変）。
   - `napoli`/`raisedVII`: §7.3.1の音程ベース定義（短2度上の短調／長7度上の長調）を直接適用。
   - 最終的に「局所主音index」と「その内部調が長調/短調どちらか」を得る。
3. **ステップ2（目的の和音を構築）**:
   - `chord.special`が設定されていれば、ステップ1の再帰を経由せず、§2の固定テーブルを直接引いて構成音を確定する。
   - なければ、局所主音に度数オフセット表を適用して根音indexを求め、3度・5度・形体（7/9/付加6/付加4）を加算する。7度・9度は内部調自身の自然音を使う（§7.9で確定した「3度ずつの機械的進行」の例外規則を反映）。
4. **ステップ3**: 上変・下変（該当箇所に±7）を適用。
5. **ステップ4**: 根省/5省・転回を適用。
6. **戻り値**: `{ notes: [...], pcs: [...], steps: [...] }`。`steps`は各段階の中間状態（根音index、選択したオフセット表、質等）を人間可読な形で残し、UIの「導出ステップ」表示にそのまま使う。

### 音名変換の特例

五度圏インデックス→音名の生成規則（`m=n+1; letter="FCGDAEH"[m mod 7]; accidentals=floor(m/7)`）には、ドイツ語表記の特例がある。`letter==="H"`かつ`accidentals<0`（フラット側）のとき、機械的な規則は"Hes"(`n=-2`)・"Heses"(`n=-9`)・"Heseses"(`n=-16`)…を導くが、実際の表記は**すべて"B"を土台にする**：`"B" + "es".repeat(-accidentals-1)`。つまり`n=-2`→**B**、`n=-9`→**Bes**、`n=-16`→**Beses**。シャープ側（`accidentals>=0`）は通常どおり"H"基準（H, His, Hisis…）のまま変更しない。さらに、`letter`が`"A"`または`"E"`（母音終わりの文字）でフラット側のとき、最初の1個は`"s"`のみ、2個目以降は`"es"`を追加する（`Es`/`As`であって`Ees`/`Aes`ではない、`Eses`/`Ases`は2フラット）。HANDOFF §5で確定済み（本セッション中に「`n=-2`のみの特例」と誤って一般化し、その後`n=-9`→"bes"の指摘で訂正、さらにTask1実装時にE/Aの母音省略規則を発見）。`core.js`の音名変換関数はこの一般規則を明示的に実装する。

### エラーハンドリング

- `chord.special`と`chord.degree`の組み合わせが理論上不成立の場合、例外を投げず`{ error: "..." }`を返す。
- `innerChain`の`degree`演算子がVII調・II調（現在の質に対して減三和音になる度数、[HANDOFF.md:610](../../../../HANDOFF.md)）を指定した場合も同様にエラー値を返す。

## テスト計画

1. `HANDOFF.md`から本セッションで検算済みの実例（III度族・VI度族、C Dur/c mollそれぞれ約16例＋入れ子2〜3階層の例）を抽出し、`test/golden.json`に`{ spec, expectedNotes, expectedPcs }`の配列として保存する。

3. TDDの順序: (a) 内部調なしの単純三和音 → (b) 準/同主/プラス/マイナスを含む1階層の内部調 → (c) 入れ子2階層以上 → (d) `chord.special`（準和音・ナポリ・ドリア・変位VII）→ (e) 形体・上変下変・転回・根省/5省の組み合わせ。各段階でRED→GREEN→REFACTORを回す。
